# 星图评估回放优化总结

最后更新：2026-08-31

## 做了什么

这轮主要把评估回放做成一条更完整、更好读的链路，让它从“能播”变成“看得懂、收得住”。

- 统一了回放关闭流程，关闭时先清理回放特效，再隐藏趋势图
- 让评估进度走到最后一步后，趋势图不再继续向前动画
- 加强了评估过程中命中星星之间的关联线，让关系更容易被看见
- 把回放每一步的节奏放慢到 `0.8s`
- 给星星标签加了最小宽度，避免远距离时缩得几乎看不见
- 统一了全局滚动条样式，让它适配当前蓝青科技风主题
- 重建了趋势图组件，清掉了之前被乱码注释破坏的结构，恢复稳定渲染

## 技术点

### 1. 回放生命周期控制

- `EvalReplay.vue` 里把播放节奏单独收口
- 播放不再靠过快的步进，而是固定间隔推进
- 关闭回放时先执行 `stopPlayback()`
- `onUnmounted()` 里也会停掉播放，避免定时器残留

### 2. 趋势图同步

- `MetricsTrendChart.vue` 每一帧都根据最新 history 重绘
- 自动 tooltip 会识别是否已经结束
- 一旦评估完成，tooltip 停在最后一步
- 完成后不再继续推进 glow phase，避免图表看起来还在“往前跑”

### 3. 命中关联可读性

- `useEvalVisual.ts` 里把命中星星之间的连线亮度调高了一些
- 仍然保持克制，不让蓝色主题下的整体画面发白
- 星星和连线的风格仍然由统一的视觉管线控制，避免各处样式分裂

### 4. 标签最小宽度

- `EffectFactory.ts` 里把标签 badge 的最小宽度从 `92px` 提高到 `120px`
- 这样远距离时标签不会缩成看不清的小块
- 这个约束是在生成纹理时处理的，不只是靠前端布局撑开

### 5. 全局滚动条主题化

- 在 `src/style.css` 里统一定义了滚动条样式
- WebKit 浏览器使用蓝青渐变 thumb 和深色 track
- Firefox 使用 `scrollbar-color` 和 `scrollbar-width`
- 这样评估面板、详情面板、调试面板的滚动条都能保持一致

### 6. 结构稳定性

- 趋势图组件不是在原文件上硬补，而是直接重建
- 这样把被乱码注释吞掉的代码结构一次性清掉了
- 后续再做趋势图和回放联动时，改动会稳定很多

## 面试话术

### 1. 为什么要优化评估回放，而不是继续加功能？

因为评估回放是这个项目里最重要的解释链路之一。它不只是展示动画，更是在告诉用户检索过程是怎么走的。回放如果太快、太乱、收尾不干净，用户就看不懂结果是怎么来的。所以我把它当成产品主流程来做，而不是当成一个附属特效。

### 2. 这次优化的核心思路是什么？

核心思路是把“看起来很热闹”改成“看起来能理解”。具体上我做了三件事：控制回放节奏、同步趋势图结束状态、增强命中星星之间的可读关系。这样既保留了视觉表现，也不会让用户在信息里迷路。

### 3. 为什么要把每一步改成 0.8 秒？

原来的节奏更像演示级效果，信息密度太高。评估场景里用户要看的是“这一步发生了什么”，不是“动画播得多快”。调到 `0.8s` 后，用户能明显看出步骤推进，也更容易把星星变化和趋势图对应起来。

### 4. 为什么要单独处理趋势图的结束状态？

因为回放结束后，趋势图还在继续动，会给人一种数据还没跑完的错觉。这个状态不一致会削弱可信度。我把趋势图的自动推进和 glow 动画都在结束时冻结住，这样视觉状态和数据状态是对齐的。

### 5. 为什么要把星星标签做最小宽度？

标签本质上是 3D 场景里的信息卡片，远近变化很大。如果只按比例缩放，远的时候会小到看不清。把最小宽度压到 `120px`，可以保证它在远景里仍然有基本可读性，这是可视化产品里很实际的问题。

### 6. 为什么全局滚动条要重做？

因为默认滚动条和当前主题不一致，看上去很突兀。这个项目里有多个可滚动区域，如果只改局部，会出现风格断裂。统一滚动条之后，界面会更完整，也更像一个成体系的产品。

### 7. 这次实现里最大的取舍是什么？

最大的取舍是“保留表现力”和“控制复杂度”之间的平衡。比如命中星星之间的关联线，我没有做得特别夸张，而是做成更清楚但仍然克制的效果。这样用户能理解关系，但不会被视觉噪声干扰。

### 8. 如果让你一句话总结这轮工作，你会怎么说？

我把评估回放从“能播放的动画”升级成了“能读懂的诊断过程”，重点解决了节奏、收尾、可读性和主题统一这四件事。
